# BSI TR-03183-2 v2.1.0 — Gap Analysis and Design

Measured 2026-10-28 against the BSI document itself (`BSI-TR-03183-2_v2_1_0.pdf`, version 2.1.0 of
2025-08-20, from the [BSI TR-03183 page](https://www.bsi.bund.de/EN/Themen/Unternehmen-und-Organisationen/Standards-und-Zertifizierung/Technische-Richtlinien/TR-nach-Thema-sortiert/tr03183/TR-03183_node.html)),
and a fresh SBOM of a VCL application with four manifest libraries, written by the CLI as it then stood
(`DelphiSBOMCLI.exe` of 2026-10-15, `--no-config --report=none`).

**Status: implemented 2026-10-28** (see "As implemented" at the end for where the code differs from the design).

Prompted by the MSys Tool Suite 1.9 SBOM Generator (Maenken Systems), which ships a TR-03183-2 profile and a
validator with rule IDs on CycloneDX 1.7.  DX.Comply v2 is on CycloneDX 1.6.

## The finding that decides it

**v2.1.0 raised the CycloneDX minimum from 1.5 to 1.6** (its change history: "update CycloneDX minimum
version requirement from 1.5 to 1.6"; section 4: "version 1.6 or higher", "Only officially released
versions").  Every SBOM DelphiSBOM writes today (`specVersion` 1.5) is non-conformant before any field is
looked at.  The TR's field mapping (its section 8.2, Tables 8 to 12) is written for CycloneDX 1.6, and two of
its required fields (`manufacturer`, licence `acknowledgement`) do not exist in 1.5.

## How the TR applies to a Delphi application

- A **component** is a logical component, a single executable file or an archive (3.2.1).
- **A binary with statically linked libraries is an unstructured, executable file** (8.1.6, first note).
  So the primary component (the `.exe`/`.dll`/`.bpl` built) is fully described: filename, SHA-512,
  executable, archive and structured properties.
- **Statically linked libraries are logical components** (3.2.2, 8.1.3): their original files cannot be
  recovered from the binary, and 3.2.1 says information "not available due to the way a component is
  assembled has to be omitted even if it is specified as a required data field, e.g. the hash or filename".
  For a logical component only these fields MUST be addressed: creator, name, version, dependencies,
  distribution licences, other unique identifiers (purl), original licences, effective licence,
  security.txt URL.
- **A runtime package or DLL shipped beside the exe is a separate file** and is fully described.
- "The component that was used during the execution of the linker MUST be listed" (3.2.1): the MAP-file
  route (`--map`) is the TR-conformant unit source; the uses-clause route is an approximation.

## Required fields against the current output

SBOM itself (5.2.1, 5.2.3; mapping Table 8 and 10):

| TR field | CycloneDX 1.6 | DelphiSBOM today | Gap |
|---|---|---|---|
| Format and version | CycloneDX >= 1.6 | 1.5 | **Fails** |
| Creator of the SBOM | `metadata.manufacturer[].url` XOR `.contact[].email` | absent | **Missing**; needs an input (config/CLI) |
| Timestamp | `metadata.timestamp` | present (UTC) | Met |
| SBOM-URI | `serialNumber` | present | Met |

Each component (5.2.2, 5.2.4; mapping Table 9 and 11).  P = primary (exe), L = logical (linked library):

| TR field | CycloneDX 1.6 | Applies | DelphiSBOM today | Gap |
|---|---|---|---|---|
| Component creator | `manufacturer[].url` XOR `.contact[].email` | P, L | `supplier` on 6 of 6 | **Wrong field**: TR 3.2.9 separates vendor/supplier from creator; map the manifest creator to `manufacturer` |
| Name | `name` (+ `group`) | P, L | 6 of 6 | Met |
| Version | `version` | P, L | 6 of 6 | Met (rule: file modification date in RFC 3339 when none exists) |
| Filename | property `bsi:component:filename` | P | absent | **Missing** (exe name from the `.dproj` output) |
| Dependencies + completeness | `dependencies` + `compositions[].aggregate` | P, L | graph on 6 of 6, `incomplete` declared | Met; 1.6 requires every component in the graph, empty `dependsOn` included (check) |
| Distribution licences | `licenses[].expression` + `acknowledgement: "concluded"` | P, L | licences on 4 of 6, no acknowledgement | **Missing** acknowledgement; 2 components unlicensed (manifest data) |
| SHA-512 of deployable | `externalReferences[type=distribution].hashes[alg=SHA-512]` | P | absent (DX.Comply unit hashes only) | **Missing**; note the place: not `component.hashes` |
| Executable property | property `bsi:component:executable` = `executable` | P | absent | **Missing** (constant for an exe) |
| Archive property | property `bsi:component:archive` = `no archive` | P | absent | **Missing** (constant) |
| Structured property | property `bsi:component:structured` = `unstructured` | P | absent | **Missing** (constant; 8.1.6) |
| Source code URI | `externalReferences[type=source-distribution].url` | P, L, if it exists | not written | Add from manifest `vendor_url` when it is a repository |
| Deployable URI | `externalReferences[type=distribution].url` | if it exists | no | Optional input |
| Other identifiers | `purl` / `cpe` | P, L | purl present | Met |
| Original licences | `licenses[]` with `acknowledgement: "declared"` | P, L, if it exists | no | Write the manifest licence as declared too |

Property names and values are from BSI's taxonomy,
<https://github.com/BSI-Bund/tr-03183-cyclonedx-property-taxonomy> (checked 2026-10-28): `executable` /
`non-executable`, `archive` / `no archive`, `structured` / `unstructured`, and `filename` free text.  The
optional effective licence is spelt `bsi:component:effectiveLicence` in the taxonomy but
`bsi:component:effectiveLicense` in the TR's Table 12; follow the taxonomy, which defines the namespace.

Also normative: an SBOM MUST NOT contain vulnerability information (3.1); a separate SBOM per software version
(3.1).  DelphiSBOM already satisfies both.

## Design

1. **Move the output to CycloneDX 1.6.**  1.6 is the TR floor and what DX.Comply writes; 1.7 gains nothing
   the TR asks for.  The post-write check's enums (component types, hash algorithms, external reference
   types, composition aggregates) move to their 1.6 sets.  The DX.Comply merger already reads 1.6 input.
2. **SBOM creator:** new `sbomCreatorEmail` / `sbomCreatorUrl` in `.delphisbom.json` and `--sbom-creator=`
   on the CLI (an `@` makes it an email, else a URL), written to `metadata.manufacturer`.
3. **Component creator:** manifest entries gain `creator_email` / `creator_url`; when absent, fall back to
   `vendor_email` / `vendor_url` with a TR warning, since TR 3.2.9 allows the vendor only when it is the
   creator.  Written to `manufacturer`; `supplier` stays as it is.
4. **Primary component file data:** locate the built binary from the `.dproj` (`DCC_ExeOutput`, platform and
   configuration) or `--binary=`; write `bsi:component:filename`, the three properties, and the SHA-512 under
   `externalReferences[type=distribution]`.  No binary found: omit them and warn (never invent a hash).
5. **Licences:** every licence gets `acknowledgement` (`concluded` for the distribution licence, `declared`
   for the original).
6. **TR conformance check** (`uSBOMValidator`, a separate pass, rule IDs such as `TR-5.2.1-CREATOR`):
   reports each missing required field per component, distinguishing primary from logical components.
   Advice only by default; `--fail-on-tr` turns findings into exit 3, like `--fail-on-unclassified`.
7. **Statically linked libraries** keep their current shape (logical components): no filename, no hash, no
   properties, as 3.2.1 directs.

Steps 1, 5 and 7 change the shape of every SBOM written; 2 to 4 only add fields; 6 writes nothing.  Old SBOMs
on disk are not read back by DelphiSBOM, so nothing stored needs converting.

## As implemented (2026-10-28)

Where the code differs from the design above, and why:

- **SBOM creator (step 2):** taken from the manifest's `supplier` (new `supplier.email`, else `supplier.url`)
  rather than a new config key and CLI option.  The supplier is who publishes the application and its SBOM, so a
  second setting would only repeat it.  The same entity is written as the application's creator.
- **Component creator (step 3):** the vendor fallback writes no warning of its own.  The TR check reports a
  component only when it has no creator at all, and the manifest loader warns about a malformed `creator_email`.
- **Licences (step 5):** every licence is acknowledged `concluded` only.  A manifest holds one licence value,
  and CycloneDX allows an expression only as the sole item of `licenses`, so a second `declared` copy could not
  be written for expressions; the TR requires the distribution (concluded) licence and asks for the original one
  only "if it exists".
- **Added beyond the design:** the application's own licence (`application_licence` in the manifest); the RTL's
  creator (`https://www.embarcadero.com`) and licence (`LicenseRef-DelphiSBOM-Embarcadero-RAD-Studio-EULA`, since
  neither SPDX nor ScanCode LicenseDB has an identifier for the RAD Studio licence; TR 6.1 rule 3); a `LicenseRef-`
  value is written as an expression, not as a licence name.
- **Dependencies:** every component now has a `dependencies` entry, empty when nothing is known, and the one
  `incomplete` composition names every component, so each component's completeness is stated (TR 5.2.2).
- **Binary location:** `DllPrefix` / `DllSuffix` apply to packages and libraries, and `{$E}` sets the extension.
  A package on the IDE's default output folder (`$(BDSCOMMONDIR)\Bpl`), or an output folder or affix naming a
  macro the parser cannot resolve (`$(Auto)`, an IDE-only environment variable), is not resolved; name the binary
  with `--binary=` (or `"binary"` in the config).  An empty or locked binary is a warning, not a failed run, and a
  file version that differs from the stated version is warned about as a possibly stale build.
- **Version from the binary (decided 2026-10-28):** with build-number auto-increment, the `.dproj` is one build
  ahead of the exe a Release build has just written, so the `.dproj` version named a build that did not exist.
  The application's version is now the binary's own file version unless one is given explicitly; the `.dproj`
  version is the fallback without a binary.

Checked against the official CycloneDX 1.6 JSON schema (`bom-1.6.schema.json`, Draft 7): DelphiSBOM's own SBOM
and the four-library application's SBOM both validate.  On that application the TR check then reports only
manifest data: no supplier email or URL, no application licence, and two licences given as names
(`Commercial`, `Proprietary`).
